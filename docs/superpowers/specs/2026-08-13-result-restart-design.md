# 결과 화면 다시 하기 설계

**날짜:** 2026-08-13  
**상태:** 사용자 승인  
**범위:** 결과 화면에서 새 관람자용 체험을 즉시 시작할 수 있게 한다.

## 의도

전시 iPad에서 한 관람자의 결과가 끝난 뒤 다음 관람자가 별도 조작 없이 새 체험을 시작할 수 있어야 한다. 결과 화면의 **다시 하기**는 현재 페이지를 완전히 새로고침해 인트로로 돌아간다.

## 선택한 동작

`showResult()`은 선택적으로 `onRestart` 콜백을 받아 48px 이상의 터치 영역을 가진 `다시 하기` 버튼을 표시한다. `main.js`는 그 콜백으로 `window.location.reload()`를 전달한다.

전체 새로고침을 쓰므로 다음의 메모리 상태가 함께 폐기된다.

- 카메라 스트림·얼굴 감지·감정 기록
- 스냅샷 타일·모자이크·스토리 엔진 진행 상태
- 열린 결과 UI와 키보드 이벤트

브라우저의 일별 익명 통계와 이미 비차단으로 전송된 공동 감정 벽 이벤트는 유지한다. 이는 이전 관람자의 통계를 지우지 않으면서도 다음 관람자 체험만 깨끗하게 분리한다.

## 접근성 및 iPad

- 버튼은 기존 `.choice-btn.save-btn`를 재사용해 최소 높이 48px과 `touch-action: manipulation`을 유지한다.
- QR 모달은 별도 오버레이이므로, 결과 화면의 버튼은 모달이 닫힌 뒤에만 조작된다.
- 새로고침 뒤 기존 인트로의 카메라 안내와 safe-area 레이아웃이 그대로 적용된다.

## 검증 기준

1. `onRestart`를 제공하면 결과 화면에 `다시 하기` 버튼이 나타난다.
2. 버튼을 누르면 전달받은 재시작 동작이 정확히 한 번 실행된다.
3. `main.js`는 재시작 동작으로 페이지 새로고침을 전달한다.
4. 전체 Vitest와 production build가 통과한다.
